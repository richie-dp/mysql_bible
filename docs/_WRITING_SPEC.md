# 写作规范（内部文件，供各章撰写者遵循）

> 本文件是《MySQL 圣经》的唯一写作契约。任何一章必须严格符合本规范，否则视为不合格。

## 1. 读者与语气

- 读者：3~8 年经验的开发者，会写 SQL、用过索引，但**没读过源码、没系统排查过线上故障**。
- 语气：像一个带过你的资深同事在白板前讲，不用"首先/其次/综上所述"这类空转结构词。
- 禁止：教科书式定义罗列、官方文档翻译腔、"某某很重要"式的无信息量句子。
- 允许：直接给判断、给取舍、给"我见过的事故"。

## 2. 事实红线（最重要）

1. **不确定的数字不要写。** 宁可用"量级"描述，也不要编造精确耗时。实验输出若未实际执行，必须写成**预期形态**并标注 `# 输出形态（未实跑，字段含义以此为准）`，禁止伪装成真实输出。
2. **版本必须准确。** 默认 MySQL 8.0.x。5.7 差异标 `[5.7]`，8.4 差异标 `[8.4]`，小版本特性标 `[8.0.13+]` 这类形式。
3. **参数名、表名、列名必须真实存在。** 写之前想清楚：这个视图在 8.0 里叫什么（例如锁信息是 `performance_schema.data_locks`，`information_schema.innodb_locks` 在 8.0 已移除）。
4. **结论必须可推到机制层。** 不许出现"一般来说索引更快"这类无法证伪的表述。每条"更快/更慢"都要有机制解释。
5. 涉及社区争议（如 RR 是否解决幻读、`count(*)` 与 `count(1)`），**必须把两种说法的边界讲清楚**，不要和稀泥。

## 6. 绘图规范

### 6.1 唯一入口：`tools/svgkit.py`

**禁止手写 SVG。** 一律用 Python 调 svgkit，它会做结构自检（越界/重叠/穿框/文字溢出）并调用技能校验器。

```python
import sys
sys.path.insert(0, "tools")
from svgkit import *

c = Canvas(960, 560, title="图 19-1　Next-Key Lock 的加锁区间",
           subtitle="非唯一索引 idx_c，值域 5 / 10 / 15")

# 分区容器
c.container(60, 90, 840, 180, "索引 idx_c 的叶子记录（按 c 排序）")

# 节点：box(x, y, w, h, 主标题, 副标题, accent=颜色)
c.box(100, 150, 120, 60, "c = 5", "id = 1", accent=BLUE)
c.box(260, 150, 120, 60, "c = 10", "id = 2", accent=BLUE)
c.box(420, 150, 120, 60, "c = 15", "id = 3", accent=BLUE)

# 连线：arrow(x1,y1,x2,y2) / arrow((x1,y1),(x2,y2)) / arrow([(x,y),(x,y),(x,y)])
c.arrow(100, 240, 540, 240, color=RED, label="gap (5,10)")
c.arrow(540, 260, 100, 260, color=GREEN, label="next-key = gap + 记录锁")

# 代码块（展示 SQL / 日志）
c.mono_box(60, 340, 420, 90, [
    "SELECT * FROM t WHERE c = 10 FOR UPDATE;",
    "-- 锁住 (5,10] 与 (10,15) 两段间隙",
], title="SQL")

# 图例
c.legend(520, 360, [(RED, "间隙锁", None), (GREEN, "临键锁", "4,2")])

c.save("docs/images/ch19-fig1.svg")   # 自动校验
```

### 6.2 可用 API

| 方法 | 用途 |
|---|---|
| `Canvas(w, h, title, subtitle)` | 画布，默认 960×600；纵向长图用 960×800 |
| `box(x,y,w,h,title,sub,accent)` | 矩形节点，`accent` 取 `BLUE/RED/GREEN/PURPLE/ORANGE/TEAL/SLATE` |
| `mono_box(x,y,w,h,lines,title)` | 深色代码块，展示 SQL / 日志 |
| `cyl(x,y,w,h,title,sub,accent)` | 圆柱体（表空间 / 缓冲池 / 磁盘） |
| `container(x,y,w,h,label)` | 虚线分组容器 |
| `diamond(cx,cy,w,h,label)` | 判断菱形 |
| `pill(x,y,w,h,label)` | 胶囊标签 |
| `arrow(...)` | 连线，支持 2/3/4 点折线，`label` `color` `dash` `width` |
| `legend(x,y,[(color,label,dash)])` | 图例 |
| `text(x,y,s,size,fill,anchor)` | 自由文本 |

### 6.3 布局规则

- 画布 960 宽，左右边距 ≥ 40px；标题占顶部 60px。
- 同层节点水平间距 ≥ 40px，层间距 ≥ 110px。
- **连线必须先算通道再画**：从 A 右边缘到 B 左边缘，用 `arrow(x1,y1,x2,y2)`；需要绕行时给显式折线 `[(x1,y1),(mid_x,y1),(mid_x,y2),(x2,y2)]`。
- 一条连线只表达一件事，不要一条线两种语义。
- 颜色语义全局统一：`BLUE` 主数据流、`RED` 危险/锁/阻塞、`GREEN` 写入落盘、`PURPLE` 日志/复制、`ORANGE` 回滚/undo、`SLATE` 跨层调用/虚线。

### 6.5 图的类型选择

| 讲什么 | 用什么 |
|---|---|
| 组件/分层结构 | 分层架构图（container + box） |
| 时序（一条 SQL 经过谁） | 泳道式时序图（竖线 + 水平箭头） |
| 状态流转（事务/锁） | 状态机（box + 圆角箭头） |
| 区间/范围（加锁、页内记录） | 数轴式区间图（box 排列 + 区间括线） |
| 数据结构（B+树、页结构） | 树形/块状图（box + 折线） |
| 对比（RC vs RR） | 双栏对照图 |
| 决策（选型） | 流程图（diamond + box） |

## 7. Markdown 细则

- 图用相对路径 `images/chXX-figN.svg`。
- 代码块必须标语言：`sql` `bash` `text` `ini` `python`。
- 表格用于对比，超过 5 列拆表。
- 加粗只用于结论句和关键术语首次出现，不要整段加粗。
- 引用块 `>` 只用于「一句话结论」和「⚠️ 高危提示」。
- 章节之间交叉引用写「见第 17 章」，不写「见上文」。
